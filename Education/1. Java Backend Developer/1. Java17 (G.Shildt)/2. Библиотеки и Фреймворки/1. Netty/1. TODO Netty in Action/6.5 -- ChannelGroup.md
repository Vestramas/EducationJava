ChannelGroup в Netty — это потокобезопасный контейнер для управления группой активных каналов (соединений). Это одна из ключевых утилит для работы с широковещательными рассылками, глобальными событиями и массовыми операциями над соединениями.

Ниже разберем его предназначение, способы создания и примеры использования.

---
# 1. Для чего нужен ChannelGroup?

Основная цель — **упростить управление множеством каналов** как единым целым.

**Ключевые возможности:**

- **Массовые операции**: отправить сообщение всем клиентам одновременно (broadcast).
    
- **Автоматическое управление жизненным циклом**: при закрытии канала он автоматически удаляется из группы (если используется стандартная реализация).
    
- **Закрытие всех каналов**: при остановке сервера можно одним вызовом закрыть все активные соединения.
    
- **Поиск и итерация**: можно перебирать каналы, проверять их состояние, отправлять сообщения выборочно.
    
- **Безопасность из коробки**: все методы потокобезопасны.
    

---

# 2. Варианты создания ChannelGroup

Netty предоставляет одну основную реализацию — `DefaultChannelGroup`

Но есть два нюанса при создании:

---
## А) Стандартный конструктор

```java
ChannelGroup group = new DefaultChannelGroup(eventLoop);
```

В конструктор ==обязательно передается== `EventExecutor` (обычно это `EventLoopGroup` или `EventLoop`). Он нужен для:

- Уведомлений о добавлении/удалении каналов.
    
- Публикации событий (например, `ChannelGroupFuture`).

### Варианты, что можно передать:

|Вариант|Пример|Когда использовать|
|---|---|---|
|**Конкретный EventLoop**|`new DefaultChannelGroup(ctx.channel().eventLoop())`|Если группа привязана к одному потоку (редко)|
|**EventLoopGroup**|`new DefaultChannelGroup(bossGroup.next())`|Если вы хотите выделить отдельный поток для группы|
|**GlobalEventExecutor.INSTANCE**|`new DefaultChannelGroup(GlobalEventExecutor.INSTANCE)`|**Самый распространенный вариант** — группа использует глобальный общий поток|

#### Что такое `GlobalEventExecutor.INSTANCE`?

Это **синглтон-экземпляр** класса `GlobalEventExecutor` из Netty, который:
- Предоставляет **единственный общий поток** (один `Thread`) для всех `DefaultChannelGroup`, созданных с ним.
    
- Этот поток существует **весь жизненный цикл JVM** (запускается при первом обращении и живет до завершения приложения).
    
- Используется для **асинхронного уведомления** — например, когда вы вызываете `group.writeAndFlush()`, операции выполняются в этом общем потоке, а не блокируют ваш текущий.

> [!WARNING] Подводный камень
> Так как `GlobalEventExecutor` использует один поток на все группы, **долгие операции** внутри этого потока (например, тяжелые вычисления в слушателях) могут замедлить все группы. 
> 
> Для высоконагруженных систем лучше использовать выделенный `EventLoopGroup`.



---
## Б) С дополнительным именем (для отладки)

```java
ChannelGroup group = new DefaultChannelGroup("server-clients", eventLoop);
```

Имя используется только в логах и трейсах — не влияет на логику.

---
#### Важно
- **Не создавайте** свой велосипед на основе `ConcurrentHashMap` и `Channel` — вы потеряете автоматическое удаление и синхронизацию с событиями канала.
    
- Используйте одну группу на весь сервер, либо создавайте отдельные группы для разных комнат/чат-румов.

# 3. Как используется (основные методы)

## А) Добавление канала в группу

Обычно это делается в `channelActive()` или после успешного хендшейка:

```java
@Override
public void channelActive(ChannelHandlerContext ctx) {
    Channel channel = ctx.channel();
    group.add(channel); // автоматически подписывается на закрытие
    System.out.println("Client connected: " + channel.remoteAddress());
}
```

---
## Б) Широковещательная рассылка (broadcast)

Отправить одно сообщение всем:

```java
group.writeAndFlush(Unpooled.copiedBuffer("Hello all!", CharsetUtil.UTF_8));
```

Этот метод возвращает `ChannelGroupFuture`, по которому можно отследить завершение отправки каждому клиенту.

---
## В) Отправка только активным каналам

```java
group.forEach(ch -> {
    if (ch.isActive() && ch.isWritable()) {
        ch.writeAndFlush(message);
    }
});
```

---
## Г) Закрытие всех соединений при остановке сервера

```java
// В методе остановки сервера
ChannelGroupFuture future = group.close();
future.awaitUninterruptibly(); // ждём, пока все каналы закроются
```

## Д) Проверка размера

```java
int count = group.size(); // количество каналов в группе
```

# 4. Расширенные сценарии использования

## А) Группы по комнатам (как в чате)

Создаете несколько экземпляров `ChannelGroup`:

```java
Map<String, ChannelGroup> rooms = new ConcurrentHashMap<>();
rooms.put("general", new DefaultChannelGroup(eventLoop));
rooms.put("tech", new DefaultChannelGroup(eventLoop));

// Присоединяем клиента к комнате
rooms.get("general").add(ctx.channel());

// Отправляем в конкретную комнату
rooms.get("tech").writeAndFlush(msg);
```

---
## Б) Удаление канала при отключении

Так как `DefaultChannelGroup` слушает событие `channelInactive` и удаляет канал автоматически — вам не нужно вызывать `remove()` вручную. Но если вы хотите выполнить доп. логику, используйте:

```java
@Override
public void channelInactive(ChannelHandlerContext ctx) {
    // group.remove(ctx.channel()); // не обязательно!
    System.out.println("Client disconnected");
}
```

## В) Получение уведомлений о завершении массовой операции

```java
ChannelGroupFuture future = group.writeAndFlush(message);
future.addListener(f -> {
    if (f.isSuccess()) {
        System.out.println("All messages sent");
    } else {
        Throwable cause = f.getCause();
        // обработать ошибки отправки
    }
});
```

# 5. Важные нюансы и подводные камни

|Нюанс|Пояснение|
|---|---|
|**Авто-удаление только при закрытии**|Канал удаляется, когда вызывается `close()` или он закрывается по ошибке. Если канал просто стал неактивным (но не закрыт) — он останется в группе.|
|**Метод `writeAndFlush()` не гарантирует порядок**|Отправка выполняется асинхронно, порядок доставки разным клиентам не гарантируется.|
|**Не храните ChannelGroup в статике без необходимости**|Это может привести к утечкам памяти, если сервер перезагружается.|
|**Для больших групп (10k+) используйте `forEach` с осторожностью**|Итерация по группе блокирует внутреннюю структуру данных на время обхода.|
|**`ChannelGroupFuture`**|Важно не путать с обычным `ChannelFuture` — у группового есть методы `successCount()`, `failureCount()` и т.д.|
